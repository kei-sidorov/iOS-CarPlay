* Доступ только к двум ресурсам автомобиля

  * mainScreen：доступ к дисплею автомобиля
  * mainAudio：доступ к динамикам и микрофону

    * Заимствование (borrow): кратковременное использование, например дисплей сейчас показывает нативный интерфейс, и в этот момент пользователю поступает звонок в CarPlay: дисплей временно переключается на интерфейс CarPlay, а после завершения звонка автоматически возвращается к нативному интерфейсу

    * На основе текущего состояния и набора правил распределяет ресурс в пользу одной из сторон

4. Управление состоянием App

* Если и CarPlay, и нативная система хотят получить доступ к ресурсам, необходимо определить правила управления состоянием App

Итак, CarPlay и нативная система автомобиля зависят от одних и тех же ресурсов и спроектированы так, чтобы сосуществовать с нативным пользовательским опытом. ## WWDC17 - Добавьте в свой App поддержку CarPlay

Эта сессия рассчитана на разработчиков. В ней кратко рассказано, как приложения работают в CarPlay, как интегрировать приложение в платформу CarPlay, каковы нормы разработки и как избежать типичных ошибок.

Возможности, доступные всем приложениям в CarPlay：

* Отображение информации о воспроизводимом аудио и элементов управления воспроизведением
* Аудио воспроизводится через динамики автомобиля
* SiriKit поддерживает некоторые подходящие интенты. Если пользователь вызовет SiriKit-интент, который CarPlay не поддерживает, Siri сообщит, что эта функция недоступна в автомобиле

Даже если ваш App не поддерживает CarPlay, пользователь может пользоваться им перед началом поездки. Для хорошего пользовательского опыта в CarPlay убедитесь, что ваш App не воспроизводит аудио при подключении к CarPlay, если это не было запрошено, потому что аудио вашего App может наложиться на то, что пользователь в данный момент слушает в CarPlay.

В некоторых случаях вашему App может понадобиться корректно взаимодействовать с другим аудио.

* Для аудио-приложений используйте следующий режим, чтобы ваше аудио приостанавливалось, пока воспроизводится другое аудио.
  * AVAudioSessionModeSpokenAudio
* Навигационные приложения могут периодически воспроизводить голосовые подсказки; для них используются следующие два протокола. Второй приостанавливает воспроизведение аудио, помеченного как «spoken audio», перед вашей аудио-репликой; поскольку навигационное аудио смешивается с другим аудио, вашу аудиосессию нужно пометить как «можно смешивать» для взаимодействия с другим аудио.
  * AVAudioSessionModeSpokenAudio
  * AVAudioSessionModeCategoryOptionInterruptSpokenAudioAndMixWithOthers

Для приложений, интегрированных с CarPlay, иконка App появляется на главном экране CarPlay, а приложение, работающее в CarPlay, отображается и на экране CarPlay, и на экране iPhone (в iOS 13 и более ранних версиях из-за отсутствия UIScene они могут находиться только вместе на переднем плане или вместе в фоне).

* Аудио-приложения могут предоставлять музыку, новости, подкасты и другой контент, используя единый дизайн, подходящий для использования в автомобиле
* Приложения для сообщений через Siri и голосовых звонков можно обновить для поддержки CarPlay
* Приложения автопроизводителей могут предоставлять специфичные для автомобиля элементы управления и отображение информации, чтобы водитель мог пользоваться ими, не выходя из CarPlay.

Приложения, не интегрированные с CarPlay, не будут отображаться в CarPlay, даже если вы выведете такое приложение на передний план на iPhone.

**Ограничения контента**

Некоторые автомобили могут принудительно показывать на экране ограниченный объём контента в зависимости от того, движется ли автомобиль. Это может ограничивать число строк, отображаемых на экране, и содержимое, доступное после перехода в тот или иной каталог. Ваш App может использовать MPPlayableContentManager для обработки этих изменений.

Чтобы узнать, ограничено ли отображаемое содержимое, реализуйте следующий метод делегата: он позволяет определить, применяются ли ограничения контента, а также получить максимальное число элементов в списке и максимальную глубину иерархии при действующих ограничениях.

```swift
extension YourAppContentManager : MPPlayableContentDelegate {
    // called whenever CarPlay state changes
    func playableContentManager(
                _ contentManager: MPPlayableContentManager,
               didUpdate context: MPPlayableManagerContext) {
        // check to see if content limits are enforced
        let contentLimitsEnforced = context.contentLimitsEnforced
        if contentLimitsEnforced {

            // the maximum depth in the hierarchy when content limits are enforced

        } else {
            …
        }
    }
}
```

Если вашему App больше подходят Tabs, а не TableView.

* Чтобы добавить tabs, добавьте `UIBrowsableContentSupportsSectionedBrowsing` в Info.plist
* Рекомендуется использовать не более 4 tabs с короткими заголовками, потому что места мало, у некоторых автомобилей узкие экраны, а при наличии воспроизводимого контента нужно ещё показывать кнопку «Исполняется»

**Changing Playback Rate**

Новая возможность iOS 11 — экран «Исполняется» поддерживает отображение и изменение скорости воспроизведения. Если вашему App нужна такая поддержка:

* Добавьте `MPNowPlayingInfoPropertyDefaultPlaybackRate` в `MPNowPlayingInfoCenter`
* И используйте массив поддерживаемых скоростей воспроизведения, хранящийся в `MPNowPlayingInfoCenter`, чтобы отвечать на команду изменения скорости воспроизведения
* Implement `changePlaybackRateCommand` with `supportedPlaybackRates` in `MPRemoteCommandCenter`

Ниже приведён пример кода, реализующего изменение скорости воспроизведения. В этом примере текущая скорость равна 1.0, а поддерживаемые варианты — 0.5, 1.0, 1.5, 2.0. Когда пользователь хочет увеличить скорость, а аудио уже воспроизводится на максимальной поддерживаемой скорости, дальнейшее увеличение циклически переходит к минимальной скорости. В этом примере, если пользователь трижды подряд увеличит скорость, она изменится так: 1.0 -> 1.5 -> 2.0 -> 0.5.

```swift
// Change Playback Rate

let infoCenter = MPNowPlayingInfoCenter.default()
infoCenter.nowPlayingInfo = [MPNowPlayingInfoPropertyDefaultPlaybackRate: 1.0,
                             … ]

let changePlaybackRateCommand = MPRemoteCommandCenter.shared().changePlaybackRateCommand
changePlaybackRateCommand.supportedPlaybackRates = [0.5, 1.0, 1.5, 2.0]
```

**Best Practices**

* Перед вызовом completion handlers в `MPPlayableContentDataSource` и `MPPlayableContentDelegate` убедитесь, что контент, который будет воспроизводиться, действительно готов к воспроизведению или отображению, а на это время показывайте индикатор активности.

**Как добавить в аудио-приложение поддержку системы CarPlay**

* Template based
* Works with all CarPlay systems
* Uses existing MediaPlayer APIs

Шаблоны, используемые CarPlay, абстрагируют разные сложности CarPlay, такие как способы ввода и размеры экранов, поэтому вашему аудио-приложению достаточно предоставить данные и показать их в CarPlay, обычно через `tableview` или `tabs`, в зависимости от того, как вы хотите представить свои данные.

Вам нужно сосредоточиться на том, как предоставлять данные CarPlay. Если вы уже разрабатываете аудио-приложение на существующих API, то, возможно, уже хорошо с этим знакомы. Ниже приведены 3 API, которые нужно знать для публикации App в системе CarPlay; каждый из них подробно объяснялся в прошлогоднем видео WWDC.

Для просмотра контента в CarPlay используется `MPPlayableContent` API с `dataSource` и `delegate`, чтобы ваше аудио-приложение могло предоставлять данные CarPlay, а делегат получал обратные вызовы. API `MPNowPlayingInfoCenter` и `MPRemoteCommandCenter` используются для разработки функциональности «Исполняется».

![](https://cdn.nlark.com/yuque/0/2021/png/12376889/1630374246223-1cad5cf8-1c87-4479-882d-aa337d98532b.png?x-oss-process=image%2Fresize%2Cw_750%2Climit_0)

Ниже приведён минимальный код, необходимый для поддержки CarPlay в аудио-приложении：

```swift
func application(
_ application: UIApplication, didFinishLaunchingWithOptions launchOptions:
[UIApplicationLaunchOptionsKey: Any]?) -> Bool {
    
    // Set up data source and delegate
    MPPlayableContentManager.shared().dataSource = SrirockaContentManager.shared
    MPPlayableContentManager.shared().delegate = SrirockaContentManager.shared
    
    // Set Now Playing metadata in MPNowPlayingInfoCenter
    let nowPlayingInfo: [String: Any] = [:]
    MPNowPlayingInfoCenter.default().nowPlayingInfo = nowPlayingInfo
    
    // Respond to remote command events
    let commandCenter = MPRemoteCommandCenter.shared()
    commandCenter.playCommand.isEnabled = true
    commandCenter.playCommand.addTarget { _ in .success }
}
```

Оптимизирован `MPPlayableContent` API: улучшена производительность того, как запрашиваются источник данных и делегат, при этом менять код не нужно. **Best Practices**

Давайте подробно разберём, как оптимизировать аудио-приложение:

* Call `reloadData()` only when needed
  * Это API из `MPPlayableContent`, который умеет лучше оптимизировать ваше аудио-приложение. Вызывать `reloadData()` следует только при необходимости: это очень дорогая операция, снижающая отзывчивость App.
* Use `beginUpdates()` and `endUpdates()`
  * Напротив, если нужно обновить только часть контента, поместите обновления между вызовами этих двух API, чтобы контент обновился корректно.
* Keep an internal representation of the data source to optimize performance
  * Вызовы `MPPlayableContent` теперь асинхронны, когда мы запрашиваем данные у вашего App. Поэтому где-то в App нужно хранить внутреннее представление или кэш информации, чтобы при запросе контента вы могли быстро её предоставить и сохранить отзывчивость App.

**Don’t Miss a Beat!**

Account for these common scenarios

* Screen locked with passcode
* Unreliable network connectivity

Теперь обсудим способы «дальнейшей оптимизации производительности аудио-приложения в CarPlay»:

Плейлист загружается нестабильно, а если App не предоставляет контент вовремя, CarPlay завершит загрузку по тайм-ауту. Чем это может быть вызвано?

* Пользователи CarPlay часто ездят там, где нет быстрого соединения, или при заблокированном экране телефона, а для разблокировки нужен пароль. Если политика защиты данных вашего App зависит от того, что телефон разблокирован, вы не сможете получить информацию своего App, и в итоге CarPlay завершится по тайм-ауту. Поэтому, если ваши данные доступны только при разблокированном телефоне, нужно пересмотреть политику защиты данных вашего App.
* Пользователи CarPlay могут ездить в местах со слабой сетью или без неё, разные системы CarPlay предоставляют разные сервисы передачи данных, и вам нужно протестировать ситуацию без постоянного подключения к Wi-Fi.

![image.png](https://cdn.nlark.com/yuque/0/2021/png/12376889/1630376442054-bafd9ea7-678c-48b2-86b8-5d2b260313f4.png?x-oss-process=image%2Fresize%2Cw_750%2Climit_0)

Как оптимизировать?

Используйте `beginLoadingChildItems()` для начальной загрузки контента.

Есть API `beginLoadingChildItems` для запуска получения контента; он вызывается всякий раз, когда любой из ваших путей индекса отображается в CarPlay (можно сравнить с методом `cellForRow` у `tableview`). Когда пользователь прокручивает `tableview` или выбирает разные `tabs`, `beginLoadingChildItems` вызывается для каждого отдельного пути индекса, показанного на дисплее. Так у вашего App появляется возможность начать загрузку до того, как пользователь реально выберет контент. Тогда к моменту выбора контента пользователем сетевой запрос либо уже выполняется, либо данные уже готовы.

```swift
func beginLoadingChildItems(at indexPath: IndexPath,
                            completionHandler: @escaping (Error?) -> Void) {
    if indexPath.indexAtPosition(2) == 0 {
        // Start fetching content that requires a network connection or needs some setup
        startProcessingHeatingHabaneros()
        
    }
    ...
    completionHandler(nil)
}
```

Далее инженер Apple привёл сценарий, с которым вы можете столкнуться при разработке приложения CarPlay.

Если вашему аудио-приложению для предоставления контента нужен вход в аккаунт, то в CarPlay опыт будет очень плохим, и пользователь не сможет взаимодействовать с вашим App. Убедитесь, что вы предоставляете какой-то вариант работы, чтобы пользователь мог хотя бы без входа в аккаунт пользоваться вашим App в CarPlay, это улучшит пользовательский опыт.
